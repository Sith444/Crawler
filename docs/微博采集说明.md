# 微博采集与恢复

微博使用热门关键词搜索，使用 Chrome、SQLite 主库，基础请求间隔为 0.5 秒，正文数量不设上限。Excel 导出开启，JSONL 默认关闭。

## 请求与暂停

搜索、全文、评论请求共用一个 HTTP 连接池和请求间隔控制器。
明确的“无评论”“搜索无内容”正常结束对应任务，不作为错误重复请求。
没有明确结束提示的正常空搜索列表会复查同一页，连续两次正常空列表才结束当前关键词；只有非帖子卡片的页面继续向后翻页。缺少卡片列表等响应异常会有限重试，失败后保留断点并暂停。
网络错误、服务端错误、HTTP 429 有限重试，默认最多三次；429 优先采用 Retry-After 等待时间。
服务端要求等待超过 60 秒、连续重试失败、验证码、登录失效或连续三次接口错误时暂停，不继续自动请求。处理浏览器提示后重新运行。
0.5 秒是基础最小请求间隔，不是固定吞吐量，也不能保证不会受到平台限制。

## 断点与缓存

`data/wb/collection_state.db` 保存关键词页码、全文缓存、评论采集状态、失败项和帖子命中的关键词。
正文与评论仍存放在 `database/sqlite_tables.db`，状态库不替代原始数据。
中断后，未完成的页会重新处理，已经完成的页从下一页继续。整轮关键词完成后，下次重新从首页搜索，以发现新内容。
平台搜索排序会变化，因此页码断点不能保证完整覆盖平台数据。
`COLLECTION_RESUME_SEARCH=False` 可从配置起始页重新搜索；全文和评论仍按各自刷新周期处理。
全文、评论默认刷新周期均为 24 小时，设为 0 可关闭相应缓存；较短周期更及时，但请求量增加。
全文缓存只复用正文，不覆盖搜索接口返回的新互动量。热度的观察时间记录为本次搜索响应取得时间。
失败的全文或评论任务会记录下来，当前搜索结束后尝试补采；仍失败的任务继续保留。

## 评论分阶段采集

正文先保存。交通相关及不确定的帖子继续采集评论，明显无关或答题内容暂缓采评论，不删除原文。
`COLLECTION_STAGED_COMMENTS=False` 可关闭评论初筛，所有帖子均按评论上限采集。
初筛会有误差，不能将暂缓评论误解为已经证明不相关；人工抽检发现问题后可关闭此开关并重扫。
每帖最多 20 条一级评论属于抽样，不能据此代表全部评论或全部用户观点。

## 周期快照与统计

默认每处理 200 条帖子或经过 600 秒，在下一次帖子/评论处理检查点导出原始快照；不需要等整个任务结束。
网络请求或重试等待期间不会承诺严格整点导出。SQLite 中已经提交的数据持续保留。
导出遵守 Excel、JSONL 各自开关，文件写入 `data/wb/export/`，均为累计快照。
正常结束或程序能够处理的中断会执行最终导出与交通筛选；强杀或断电时，依靠 SQLite 和搜索状态恢复。
日志中的 saved_posts 为处理并保存次数，可能包含更新记录，不等同于唯一新增帖数；detail_cache_hits、comment_skips 等用于观察重复请求减少情况。

## 人工抽检

筛选 Excel 新增“人工抽检”页，对热点候选、相关非热点、相关性剔除各抽取最多 50 条，保留原文、系统理由和分数。
重复帖子及缺少帖子 ID 的记录不参加语义相关性抽检。
`human_related` 填 1（相关）或 0（无关）；`human_hot` 填 1（认为值得列为热点候选）或 0；`review_notes` 记录依据。
人工列默认留空，程序不会虚构准确率。分层样本不能直接不加权地当作总体准确率；需结合各组总体数量评价误保留和漏筛，再调整规则。
