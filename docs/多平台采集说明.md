# 多平台采集说明

微博、小红书、抖音、快手、B站、贴吧和知乎均已接入平台独立的导出与交通筛选。六个新增平台的普通关键词搜索接入统一的续采流程，登录与内容解析仍使用各平台接口。

各平台已完成代码适配和离线模拟验证，真实接口可用范围需要分别核查。平台通过启动参数选择，默认配置以`config/base_config.py`为准，没有设置每平台采集数量目标。

## 已接入功能

| 功能 | 行为 |
| --- | --- |
| 请求控制 | 复用连接，统一控制接口请求间隔；网络异常、5xx 和 429 有限重试，遵守 Retry-After |
| 暂停 | 登录失效、验证或访问限制停止当前采集；连续异常达到限制后停止重试 |
| 续采 | 按平台、关键词和搜索参数保存下一页及平台游标；未完成页面中断后重放 |
| 详情缓存 | B站、小红书、贴吧、知乎详情在有效期内复用；抖音、快手搜索已含内容时直接保存 |
| 评论 | 优先获取交通相关及待确认内容的评论；近期完成的评论任务跳过；失败任务保留供下次补采 |
| 周期快照 | 默认每新增保存 200 条内容或经过 600 秒，在内容处理边界检查并导出 |
| 保存与导出 | SQLite 持续落库；Excel 开启，JSONL 开关默认关闭；结束或可处理的中断后导出 |
| 筛选 | 清理正文、按平台标识去重、筛选道路交通内容、关联评论、平台内选取前 20% 热点候选 |
| 人工抽检 | 热点、相关非热点、相关性剔除三组各抽最多 50 条，人工标签留空 |

小红书默认使用 `XHS_COMMENT_MODE="browser"`，读取已登录笔记网页正常加载的一级评论响应，通过滚动加载后续页，仍受单篇评论数量上限控制。设置为 `"api"` 可使用独立接口请求。网页加载超时、验证或非成功响应时暂停并保留进度；接口模式收到 HTTP 406 时也立即暂停。诊断日志只记录接口路径、状态及业务码，不输出 Cookie、访问凭证或签名。

断点续采面向普通关键词搜索。B站的时间范围搜索、指定内容和作者模式保留原有流程，不保证具有关键词搜索的全部续采功能。强制结束进程或断电时可能无法生成最终 Excel，但此前已提交的 SQLite 数据仍在。

## 平台字段与候选排序

| 平台 | 标识 | 正文 | 排序依据 |
| --- | --- | --- | --- |
| 微博 `wb` | 帖子 ID | 正文 | 论文网络传播力公式：点赞、评论、转发与时间衰减 |
| B站 `bili` | 视频 ID | 标题、简介 | 将点赞、评论、分享映射到上述公式，需单独验证适用性 |
| 小红书 `xhs` | 笔记 ID | 标题、正文 | 将点赞、评论、分享映射到上述公式，需单独验证适用性 |
| 抖音 `dy` | 作品 ID | 标题、描述 | 将点赞、评论、分享映射到上述公式，需单独验证适用性 |
| 快手 `ks` | 作品 ID | 标题、描述 | 当前保存的点赞数 |
| 贴吧 `tieba` | 帖子 ID | 标题、正文 | 当前保存的回复数 |
| 知乎 `zhihu` | 内容 ID 与内容类型 | 标题、正文、描述 | 当前保存的赞同数与评论数之和 |

快手、贴吧、知乎的排序是可用互动指标，未套用缺字段的微博公式，也不是论文验证过的热度模型。缺失值不补成零。各平台分数仅用于平台内排序，不能直接合并比较。知乎相同数字 ID 的回答、文章和视频分别处理。

## 配置入口

修改 `config/base_config.py` 的 `PLATFORM` 选择单个平台；`CRAWLER_TYPE="search"` 使用关键词搜索。关键词仍由 `KEYWORDS` 配置。`CRAWLER_MAX_NOTES_COUNT=0` 在普通关键词模式下不设数量上限，直到平台无结果或页面重复，不保证平台会返回全部历史内容。

微博请求间隔为 0.5 秒，抖音为 10 秒，小红书为 2 秒；其余平台在 `PLATFORM_COLLECTION_OPTIONS` 中默认 1 秒。该值是最小请求启动间隔，实际还受响应耗时、重试退避和平台原有必要等待影响。

每个平台支持以下覆盖项：`interval`、`attempts`、`backoff`、`max_wait`、`resume`、`detail_hours`、`comment_hours`、`staged_comments`、`snapshot_posts`、`snapshot_seconds`。未覆盖时读取 `COLLECTION_*` 公共默认设置。微博专用的搜索类型、全文开关等仍使用微博专用名称。


抖音当前请求间隔为 10 秒，不设数量上限，按每个关键词的游标持续向后翻页。不会定时回到首页重新搜索。平台明确返回无更多结果后，处理下一个关键词。响应异常或未说明是否还有结果的空响应会暂停并保留断点，不把这些情况记录为搜索完成。接口说明还有更多结果且游标前进时，偶发空页或没有视频的综合搜索页仍继续翻页；作品页面完全重复且没有新作品时，停止当前关键词翻页。登录失效、验证和访问限制仍暂停。按一次 Ctrl+C 可停止并保存进度。

普通关键词搜索的七个平台共用 `CRAWLER_MAX_NOTES_COUNT=0`，不设置小数量目标。各平台按自身分页信息持续向后获取，不定时返回首页重跑，也不自动同时运行其他平台。

| 平台 | 翻页依据及空页处理 |
| --- | --- |
| 微博 | 按页码前进；过滤后的非帖子卡片页继续；没有结束标记的正常空列表复查同一页 |
| B站 | 按页码及 `numPages` 前进，未到总页数时继续；无总页数的正常空列表复查 |
| 小红书 | 保持搜索会话，识别布尔值、数字和字符串形式的 `has_more`；推荐搜索词页不当作结束 |
| 抖音 | 按搜索偏移量和会话前进，明确有更多时允许跳过非视频页；异常状态保留断点 |
| 快手 | 按服务端 `pcursor` 前进，缺失游标不能当作 `no_more`；保留搜索会话 |
| 贴吧 | 每页完整保存帖子；综合卡片页继续；保留原始卡片数量和 `has_more` 供结束判断 |
| 知乎 | 保留服务端 `paging.is_end` 和下一页偏移量；只有问题、用户等不支持内容的页面仍继续翻页 |

复查适用于正常结果列表确实为空且缺少分页结束标记的情况：同一页连续两次正常空列表才视为没有更多。缺少必要字段或游标异常按公共重试参数重试，默认最多三次，仍异常则暂停并保留断点，不把关键词标为已完成。验证、登录失效和明确访问限制不会被当作空页反复请求。平台返回的可见搜索范围仍可能受登录状态和服务端限制影响，不能据此保证获取全部历史数据。

抖音搜索排序在 `config/dy_config.py` 的 `DY_SEARCH_SORT_TYPE` 设置：`0` 为综合，`1` 为最多点赞，`2` 为最新发布。当前为 `1`。排序方式参与断点标识，切换排序后从配置起始页采集，不沿用其他排序的页码和游标；原始数据按作品 ID 更新。最多点赞是平台搜索排序，不等于后续筛选的论文热度分数。

例如，仅调整小红书的间隔和缓存有效期：

```python
"xhs": {"interval": 2, "detail_hours": 24, "comment_hours": 24},
```

`SQLITE_EXPORT_EXCEL=True` 开启 Excel；`SQLITE_EXPORT_JSONL=False` 关闭 JSONL。两个开关同时用于原始数据和筛选结果的格式导出。SQLite 为主存储，不依赖 Excel 是否导出成功。

## 数据位置

默认原始 SQLite 为 `database/sqlite_tables.db`，各平台使用各自的数据表。导出、筛选和续采记录分平台存放，不把不同平台内容混进同一份 Excel：

```text
data/
  wb/                         微博
  bili/                       B站
  xhs/                        小红书
  dy/                         抖音
  ks/                         快手
  tieba/                      贴吧
  zhihu/                      知乎
    collection_state.db       该平台的断点、缓存与补采任务
    export/时间戳/            原始数据 Excel；启用后另有 JSONL
    filtered/时间戳/          筛选数据库与 Excel；启用后另有 JSONL
```

微博已有独立续采记录，文件名以微博采集说明为准。更改 `SAVE_DATA_PATH` 时，以该目录替代 `data`。筛选不会删除或覆盖原始数据库中的内容。

## 验证方式

离线测试覆盖六个平台的原生客户端连接复用、访问限制暂停、平台搜索/详情/评论字段适配、游标恢复、平台状态隔离，以及七个平台的筛选与 Excel 导出。测试使用临时数据库和模拟响应，不访问平台，不写入正式采集数据。真实可采集范围、当前接口可用性和登录状态仍需逐个平台实际验证。
